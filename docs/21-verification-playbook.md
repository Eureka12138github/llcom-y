# 21 · Agent 验证手段与分工约定

> 目的：明确哪些改动可以由 Agent 自动验证、哪些更适合用户手动验证，避免“验证脚本比改动本身还费时间、还不一定对”。

---

## 1. 基本原则

1. **验证成本要低于改动成本**。如果为了证明一个视觉/交互效果要写多个脆弱脚本，优先请用户手动验证。
2. **一种手段通常不够**。至少组合“构建/测试 + 目标场景检查”；不要只凭编译通过就声称功能正常。
3. **自动验证要可重复**。优先用命令、单元测试、文件内容、UIA 可读状态；少依赖鼠标坐标、窗口焦点和像素级截图。
4. **手动验证也要有明确预期**。不能只说“你试试”，要给出步骤、预期结果和失败时要提供的信息。
5. **不夸大结论**。回复中写清“已验证什么、没验证什么、剩余风险”。

---

## 2. Agent 可用的验证手段

| # | 手段 | 能证明什么 | 主要限制 / 成本 |
|---|---|---|---|
| 1 | **构建** | 代码能编译、XAML 能加载、资源/引用/目标框架正确 | 不能证明运行行为；运行中的 exe 会锁住输出 |
| 2 | **单元 / 集成测试** | 纯逻辑、解析器、服务、ViewModel、数据缓冲、文件输出、Lua API 等 | 现有测试不覆盖 WPF 渲染和真实交互；需要新增测试 |
| 3 | **i18n 校验** | `messages.json` 与语言 XAML 一致、key 完整 | 只证明文案资源一致，不证明界面显示效果 |
| 4 | **文件内容比对** | 导出的 txt/csv/json、日志、配置、生成的脚本内容正确 | 需要能定位输出文件；不证明 UI 呈现 |
| 5 | **启动冒烟** | 程序能启动、进程存活、没有崩溃/fatal.log、没有意外写日志 | 只能证明“能启动”，不能证明具体页面交互 |
| 6 | **UI Automation（UIA）** | 查找控件、切换 Tab、选择下拉项、点击按钮、读取名称/选中状态/可见性 | WPF 部分控件没有合适的 Pattern；看不到控件内部像素；焦点/前台可能影响操作 |
| 7 | **截图 + 目视检查** | 布局、颜色、图标、文字、曲线形状等粗粒度视觉结果 | 不是像素级断言；WPF 硬件内容/遮挡/DPI 可能导致截图空白或偏差；主观效果需用户判断 |
| 8 | **模拟输入（Win32）** | 鼠标移动/点击/滚轮、键盘、窗口移动/缩放 | 前台焦点锁、终端遮挡、DPI、多屏下很容易失效；不适合作为最终证据 |
| 9 | **性能/资源测量** | 进程 CPU 时间、耗时、内存、操作耗时（Stopwatch） | 不能直接测 FPS/延迟/主观流畅度；需要对照基线 |
| 10 | **Lua 脚本执行** | `apiAddPoint`、导出 API、回调、脚本生命周期等 | 通过 UI 自动化启动脚本受焦点影响；纯 Lua 逻辑可用单元/集成测试 |
| 11 | **本地网络/回环** | TCP/UDP/MQTT 等网络工具的部分收发行为 | 需要临时服务器和 UI 操作；真实设备/网络环境另说 |
| 12 | **仓库/CI 等价检查** | 分支、diff、提交、构建命令、CI 工作流是否一致 | 不能代替真实 GitHub Actions；推送需用户同意 |
| 13 | **剪贴板/配置检查** | 复制结果、`settings.json` 是否持久化 | 只能证明数据，不证明视觉/交互手感 |

> 另外还有 **用户手动验证**：真实串口/USB、真实 Excel、系统 DPI/多屏、拖拽/滚轮/快捷键、主观流畅度、安装包等，属于 Agent 不可靠覆盖的部分。

---

## 3. 什么时候 Agent 自己验证

满足以下条件时，优先 Agent 验证：

- 改动是**纯逻辑/数据/文件输出**，可以写或已有单元测试；
- 只需要**构建 + 测试 + i18n 校验**；
- 只需要**一次启动 + 一张截图**做粗粒度视觉确认；
- 交互可以通过 **AutomationId/名称**稳定定位，操作步骤简单（切 Tab、选下拉、点按钮、读状态）；
- 验证过程**不影响用户正在使用的实例/配置**，或者可以用另一个构建目录隔离；
- 预计验证时间 **≤ 5 分钟**，且脚本不需要复杂坐标/焦点技巧。

Agent 验证后应报告：执行的命令、结果、覆盖范围、未覆盖项。

---

## 4. 什么时候直接请用户手动验证

出现以下情况时，不要硬写自动化脚本，直接给用户简洁步骤：

- 需要**真实串口/USB/网络设备**、真实电表、真实 Excel/Office；
- 涉及**屏幕缩放/DPI、多显示器、窗口最大化/拖动分隔条、鼠标滚轮/拖拽/复杂快捷键**；
- 需要判断**视觉质量/流畅度/闪烁/卡顿/手感**；
- 需要**长时间运行**、反复停止/启动、真实使用节奏；
- 需要改**系统设置、注册表、安装包/MSIX、杀毒/权限**；
- 自动化需要多个脚本、模拟前台、坐标点击，且**可靠性低**；
- 预计验证成本 > 改动成本。

## 5. 请用户验证时的标准格式

请求手动验证时，至少给出：

1. **用哪个程序**（完整路径/配置，如 `artifacts\Release\x64\llcom-y.exe`）；
2. **前置条件**（关闭旧实例、清空配置、准备设备等）；
3. **3~5 步操作**，按顺序；
4. **每一步/整体的预期结果**；
5. **失败时提供什么**（截图、`logs/fatal.log`、Lua 日志、导出文件等）。

模板：

```text
请帮我验证一下：

1. 先关闭已运行的 llcom-y（如果开着）。
2. 运行 artifacts\Release\x64\llcom-y.exe。
3. 打开「工具 → 曲线」，运行「绘制曲线演示.lua」。
4. 等约 10 秒，用鼠标滚轮缩小。

预期：
- 曲线从右向左滚动，最新点在右边缘；
- 滚轮只缩放 X 轴，Y 轴不变；
- 向左能看到更早的波形。

如果不符合，请发截图，并说明是哪个步骤。
```

## 6. Agent 自动验证后的报告格式

```text
已验证：
- 构建：...
- 单元测试：...
- 目标场景：...

未验证 / 风险：
- ...

如果需要你确认：...
```

不要写“已修复/正常”而不说明验证范围。

## 7. 场景速查

| 场景 | 首选验证 | 备注 |
|---|---|---|
| 解析器/算法/数据缓冲 | 单元测试 | 最可靠、最便宜 |
| 导出 txt/csv/json/日志 | 生成文件后比对内容 | 可验证编码、行数、转义 |
| 设置持久化 | 操作后读 `settings.json` | 注意防抖保存 |
| 按钮/菜单/Tooltip/启用状态 | UIA 读名称/状态 + 截图 | 需要 AutomationId/稳定名称 |
| 页面布局/重叠/换行 | 截图（指定窗口尺寸） | 拖拽/DPI/多屏建议用户验证 |
| 主题/颜色/图标 | 浅色/深色截图 | 原生标题栏、DPI 细节用户确认 |
| 曲线/波形/缩放 | 截图 + UIA 操作 | 流畅度/滚轮手感用户确认 |
| 串口/USB/真实设备 | 用户手动 | 本机无可靠回环设备 |
| TCP/UDP/MQTT | 本地回环 + 用户 | 真实网络环境用户确认 |
| Excel 文件 | 解析文件结构/内容 + 用户打开 | 真实 Excel 的格式/公式用户确认 |
| 性能/内存/CPU | 进程指标 + 用户体感 | 不能直接测 FPS |
| 安装包/MSIX | 用户/CI | 本地不替代真实安装 |

## 8. 本项目执行注意事项

- 本机**没有 ripgrep**，检索用 PowerShell `Select-String` / `Get-ChildItem`。
- 构建前确认 `llcom-y` 未运行，否则 `artifacts\...\llcom-y.exe` 被占用会报 `MSB3027/MSB3021`。
- 输出统一在 `artifacts\{Debug|Release}\{x64|x86}\`；exe 必须叫 `llcom-y.exe`。
- 程序**不能在压缩包/临时目录**直接运行；不要为了隔离复制到 `%TEMP%`。
- 多开检测按**程序目录**：不同文件夹可以并行；同一文件夹会弹“多开”提示。
- UI 自动化 / 截图前：确认没有残留进程、必要时删除 `lock`、把窗口移回屏幕内。
- UIA 能拿到控件外框和名称，但**看不到内部滚动区域/像素内容**；布局问题优先截图/真实控件诊断。
- `PrintWindow` 适合截取 WPF 窗口（可在遮挡时工作），但硬件加速内容可能空白；`CopyFromScreen` 需要窗口在前台。
- 模拟鼠标滚轮/拖拽很容易被前台焦点锁影响；不要把“脚本模拟成功”当成用户手感的证明。
- i18n 唯一源是 `i18n/messages.json`；改完运行 `scripts/generate-i18n.ps1`，CI 会校验。
- 临时 harness 引用 `llcom-y.exe` 时要放在同目录；`internal` 类型走反射；含中文的 `.ps1` 用 UTF-8 with BOM。

## 9. 维护

新增验证脚本、CI 检查或稳定的 UIA 操作方式时，补充到本文档；不要把详细脚本塞进 `AGENTS.md`，保持其精简。
