# DL/T 645-2007 组帧工具设计（草案）

> 状态：**设计/评估，未实现代码**。  
> 计划分支：`feature/dlt645-tool`。本文件先记录设计，后续在独立分支实现；`feature/refactor-continue` 继续做其他功能。
> 协议版本：首版只做 **DL/T 645-2007**，不兼容 1997。

## 1. 定位

不要只做“地址 + 控制码 + DI + 前导符 + 校验和”的传统表单。  
目标是做一个**协议助手**：

> 用户描述“对哪块表做什么”，工具负责生成正确帧、发送、接收、校验和解释；同时保留高级模式，让熟悉协议的人可以完全控制字节。

设计原则：

- **向导优先，高级可达**：常用操作少输入，底层字段仍可手改。
- **双向而不是单向**：不只组帧，还要解析应答。
- **可解释**：每个字节段有标签，错误有具体原因。
- **可复用**：地址簿、模板、历史、快捷发送/Lua 导出。
- **安全**：写操作、广播地址、批量操作必须确认；不做自动地址扫描。
- **可测试**：协议逻辑独立于 UI，用已知报文做单元测试。

## 2. 重点功能：通讯连接 / 自动读取表地址

### 2.1 使用场景

用户只知道总线上的表可以用通配地址 `AAAAAAAAAAAA` 读地址，但不知道实际表地址。  
工具提供一个“**通讯连接 / 读取表地址**”按钮：

1. 使用当前已打开的串口；
2. 发送“读通信地址”请求；
3. 等待并解析应答；
4. 自动把实际地址填入表地址栏；
5. 可选保存到地址簿；
6. 成功后状态显示“已连接：550000000000”。

### 2.2 读地址请求（645-2007）

公开资料中的示例：

```text
FE FE FE 68 AA AA AA AA AA AA 68 13 00 DF 16
```

- `FE`：前导字节，可选，通常 1–4 个；不参与校验和；
- `AA AA AA AA AA AA`：通配/缩位寻址地址；
- `13`：控制码，读通信地址；
- `00`：数据域长度 L；
- `DF`：校验和；
- `16`：结束符。

前导 FE 的数量要可配置，因为不同厂家可能要求不同数量，甚至不需要 FE。

### 2.3 读地址应答示例

```text
FE FE 68 00 00 00 00 00 55 68 93 06 33 33 33 33 33 88 45 16
```

- `93`：从站正常应答“读通信地址”；
- `06`：数据域长度 6；
- 数据域 `33 33 33 33 33 88`；
- 每个数据字节减 `0x33` 后得到 `00 00 00 00 00 55`；
- 地址按低字节在前传输，显示时反转字节顺序，得到 `550000000000`；
- `45`：校验和；`16`：结束符。

实现时要同时校验：

- 起始/结束符；
- 地址域与数据域是否一致；
- 控制码是否为正常应答 `0x93`；
- 长度是否为 6；
- 校验和；
- 异常应答/超时。

### 2.4 交互细节

- 地址为空时，突出“读取表地址”按钮；
- 读取成功后自动填充地址，并可自动保存为“地址簿”中的表；
- 读取失败时：
  - 显示超时、校验失败、异常应答等具体原因；
  - 提供重试；
  - 允许调整 FE 数量；
  - 允许手动输入地址；
- 总线上有多块表时，通配地址可能收到多个应答，工具应提示“收到多个地址”，让用户选择，而不是随便取第一个；
- 只读地址，不发送写命令，不自动改表参数；
- 若串口未打开，提示先在主界面打开串口，不悄悄替用户打开。

这个按钮本质上是“**先建立通信，再配置后续读写**”的第一步，比让用户先翻表壳找地址方便很多。

## 3. 页面形态

建议一页式，紧凑布局：

```text
┌ DL/T 645-2007 ─────────────────────────────────────────────┐
│ 表地址 [000000000001] [地址簿▼]  [读取表地址]              │
│ 操作   [读数据▼]  数据标识 [02010100 电压▼]                │
│ 数据域 [（读请求为空）]  前导 FE [3]   [高级设置▼]          │
│ [生成帧] [发送] [复制] [保存模板]                           │
├ 帧预览 ────────────────────────────────────────────────────┤
│ FE FE FE | 68 | 01 00 00 00 00 00 | 68 | 11 | 04 | ...     │
│ 地址 000000000001 | 长度 4 | 校验 6B | 2007                  │
├ 应答解析 ──────────────────────────────────────────────────┤
│ [等待应答] 超时 1000ms   [粘贴帧解析]                       │
│ 地址... 控制... DI... 数据... 校验通过                       │
│ 电压：220.1 V    原始：...                                  │
└ 历史 / 模板 / 地址簿 ──────────────────────────────────────┘
```

### 向导模式

常用操作：

- 读数据（选 DI）
- 读通信地址（自动/通配）
- 读时间
- 写数据（展开密码/操作者代码/数据）
- 广播校时（需确认）

操作决定控制码和数据域结构；用户不需要记 `0x11`、`0x13`、`0x14`。

### 高级模式

展开后可修改：

- 原始控制码 C；
- 原始 DI；
- 原始数据域；
- 前导 FE 数量；
- 校验和是否自动计算/手动覆盖；
- 直接粘贴完整帧解析。

高级模式不隐藏，避免变成“只能按向导走”的黑盒。

## 4. 智能功能优先级

### 第一版（推荐）

- 表地址：手动输入 + `AAAAAAAAAAAA` 通配 + **自动读取地址**；
- 操作向导：读数据、读地址、写数据；
- DI 下拉/手输；
- 自动长度、校验和、前导 FE；
- BCD 地址和低字节在前转换；
- 实时帧预览、分段解释；
- 发送/复制；
- 粘贴应答解析，校验和/长度错误提示；
- 保存简单模板；
- 最近历史。

### 第二版

- 地址簿（表名、地址、备注）；
- 常用 DI 目录（名称/单位/数据格式）；
- 自动等待应答、超时重试；
- 应答数据 `-0x33`、BCD、单位和小数位解码；
- 一键读多个 DI；
- 导出 CSV / 保存为快捷发送 / 生成 Lua 脚本；
- 多表管理。

- 自动写表；
- 1997 兼容；
- 图表、长时间轮询、数据库。

## 5. 协议实现要点

### 5.1 帧结构

```text
[FE...] 68 A0 A1 A2 A3 A4 A5 68 C L DATA CS 16
```

- 地址：6 字节 BCD，低字节在前；12 位十进制；
- `L`：数据域字节数；
- `CS`：从第一个 `68` 到数据域最后一个字节的算术和，模 256；
- `FE` 不参与校验；
- 数据域在 2007 中通常需要每个字节 `+0x33` 后传输，接收时 `-0x33`；
- 读数据请求的数据域是 DI；写数据还包含密码/操作者代码/数据；
- 控制码方向位、异常位、后续帧位要正确识别。

### 5.2 常用操作

| 操作 | 控制码（待按标准表核对） | 数据域 |
|---|---|---|
| 读数据 | `0x11` | 4 字节 DI |
| 读通信地址 | `0x13` | 空 |
| 写数据 | `0x14` | DI + 密码/操作者 + 数据 |
| 正常应答读数据 | `0x91` | DI + 数据 |
| 正常应答读地址 | `0x93` | 6 字节地址（+0x33） |
| 异常应答 | `0xD?` | 错误信息字 |

控制码表必须在实现前用标准/实测帧校准，不能只凭记忆写死。

### 5.3 DI 目录

第一版可以内置少量常用 DI，后续用 JSON 扩展：

- A 相电压 `02 01 01 00`
- A 相电流 `02 02 01 00`
- 瞬时有功功率 `02 03 00 00`
- 功率因数 `02 06 00 00`
- 正向有功总电能 `00 01 00 00`
- 组合有功总电能 `00 00 00 00`

注意：DI 的字节顺序、数据长度、小数位、单位可能随表和厂家不同，必须按表手册/实测校准；工具应允许手输 DI 和自定义解码。

## 6. 技术拆分

建议：

- `llcom/Services/Dlt645/Dlt645Codec.cs`
  - 组帧、校验和、BCD 地址、FE、数据 ±0x33；
  - 解析、校验、错误原因；
  - 纯逻辑，无 WPF 依赖。
- `Dlt645Catalog.cs`
  - 控制码/操作、DI 名称/单位/格式；
  - 首版代码内置，后续 JSON。
- `Dlt645Session.cs`
  - 订阅 `Global.uart.UartDataRecived`；
  - 处理分包/粘包、超时、请求应答匹配；
  - 只观察，不影响主日志。
- `Dlt645ViewModel.cs` + `Dlt645Page.xaml`
  - 输入、校验、预览、地址簿、模板、历史。
- 测试
  - 读地址请求/应答的已知帧；
  - 地址 BCD、L、CS、FE、+0x33；
  - 异常/超时/多应答；
  - 不在 UI 线程执行阻塞等待。
