# 改进记录

本目录用于记录**日常使用软件过程中**产生的需求、体验问题与优化方向，作为后续评估与排期的输入。

## 记录方式

- 每条建议单独成节，标题带日期，便于追溯。
- 建议包含：场景 / 现状 / 期望 / 优先级 / 状态。
- 状态取值：待评估、已评估、已实现（待验证）、已采纳、已实现、暂不处理。

> 2026-11-09 这批建议的评估结果、优先级、依赖和建议批次见
> [`docs/17-improvements-plan.md`](../17-improvements-plan.md)。
>
> **当前状态（2026-11-10）**：20 条建议中 **18 条已实现、2 条未实现**。

- 说明：读数据应答的「数据」字段改为高位在前展示（`26 11 11 03`），便于阅读；线序原值仍可在「原始帧」和「传输数据域」中查看。

### [2026-11-11] LLCOM串口打开异常

- 场景：LLOCM串口
- 现状：选择好COM口后，打开串口，显示打开成功，但尝试发送数据时又提示请打开串口，而此时显示的串口状态是打开的。需要重新关闭串口再打开方可正常发送数据
- 期望：上面那个现象不是每次都这样，是具有偶然性的，评估一下是否为代码问题
- 优先级：高
- 状态：已实现（2026-11-11，待验证）
- 原因：`SerialPortService.refreshSerialDevice()` 把释放旧串口的 `Task.Run` 里直接引用字段 `serial`/`lastPortBaseStream`。后台线程真正执行时字段可能已指向刚打开的新串口，于是把新串口 Dispose 掉：UI 仍显示“已打开”，但 `IsOpen` 已是 false。另外，端口列表刷新（手动刷新、任意 USB 事件）在串口已打开且端口仍在时也会重复 `Open()`，与后台释放旧句柄抢时序，失败后 UI 不更新。
- 实现：后台释放前先把旧 `SerialPort`/旧 `BaseStream` 捕获到局部变量；`_isOpeningPort` 提前到 UI 线程置位并用 `finally` 复位；新增 `_portLostWhileOpen`，只有端口真的从列表消失后再插回才自动重连，端口仍在时不重复 `Open()`。
