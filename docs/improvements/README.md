# 改进记录

本目录用于记录**日常使用软件过程中**产生的需求、体验问题与优化方向，作为后续评估与排期的输入。

## 记录方式

- 每条建议单独成节，标题带日期，便于追溯。
- 建议包含：场景 / 现状 / 期望 / 优先级 / 状态。
- 状态取值：待评估、已评估、已实现（待验证）、已采纳、已实现、暂不处理。

> 2026-11-09 这批建议的评估结果、优先级、依赖和建议批次见
> [`docs/17-improvements-plan.md`](../17-improvements-plan.md)。

### [2026-11-11] 645小工具帧解析优化

- 场景：645小工具帧解析
- 现状：解析原始帧: FE FE FE FE 68 02 00 00 00 00 00 68 91 08 01 01 00 04 03 11 11 26 BC 16时，数据标识 (DI)被解析为: D1CDCECE，数据被解析为: D0 DE DE F3
- 期望：数据标识应该被解析为: 04 00 01 01、数据应该是26 11 11 03
- 优先级：高
- 状态：已实现（2026-11-11，待验证）
- 实现：帧解析的数据域换算跟随「主日志减 33H」选项。勾选时输入视为已减 33H，不再重复换算；未勾选时按标准 +33H 换算。解析结果新增「数据换算」行，鼠标悬停解析按钮有说明。
- 说明：读数据应答的「数据」字段改为高位在前展示（`26 11 11 03`），便于阅读；线序原值仍可在「原始帧」和「传输数据域」中查看。
- 补充：「传输数据域」统一按 +33H 重新编码显示，始终代表线上传输形态。这样勾选「主日志减 33H」时不会和已还原的「数据域」变成完全相同的两行。

### [2026-11-11] LLCOM串口打开异常

- 场景：LLOCM串口
- 现状：选择好COM口后，打开串口，显示打开成功，但尝试发送数据时又提示请打开串口，而此时显示的串口状态是打开的。需要重新关闭串口再打开方可正常发送数据
- 期望：上面那个现象不是每次都这样，是具有偶然性的，评估一下是否为代码问题
- 优先级：高
- 状态：已实现（2026-11-11，待验证）
- 原因：`SerialPortService.refreshSerialDevice()` 把释放旧串口的 `Task.Run` 里直接引用字段 `serial`/`lastPortBaseStream`。后台线程真正执行时字段可能已指向刚打开的新串口，于是把新串口 Dispose 掉：UI 仍显示“已打开”，但 `IsOpen` 已是 false。另外，端口列表刷新（手动刷新、任意 USB 事件）在串口已打开且端口仍在时也会重复 `Open()`，与后台释放旧句柄抢时序，失败后 UI 不更新。
- 实现：后台释放前先把旧 `SerialPort`/旧 `BaseStream` 捕获到局部变量；`_isOpeningPort` 提前到 UI 线程置位并用 `finally` 复位；新增 `_portLostWhileOpen`，只有端口真的从列表消失后再插回才自动重连，端口仍在时不重复 `Open()`。

### [2026-11-11] LLCOM 右侧栏UI优化

- 场景：LLOCM右侧栏UI
- 现状：发送一个数据帧，显示在主日志框，此时右侧栏往右压缩至最小，此时将软件左边框往右压缩，直至主日志报文换行，此时将右侧栏往左拉伸，将无法做到，后续即使左侧边框已经往左拉伸，留够距离，此时右侧栏仍无法向左拉伸，必须先清除主日志框中的报文，方可拉伸。但如果在刚开始的时，右侧栏并非压缩至最小状态，则没有以上提到的限制
- 期望：右侧栏压缩至最小时，主日志框中的报文不会影响右侧栏的拉伸，仔细评估一下右侧栏压最小时，主日志框为何影响其后续的拉伸
- 优先级：中
- 状态：已实现（2026-11-11，已验证）
- 原因：左右两列原来都是 `*`。`GridSplitter` 拖动两星列时会把星号权重改写成“1 星 = 1 像素”的等价值；窗口缩放让某一列触到 `MinWidth` 后，实际宽度和星号比例脱节，拖动时 GridSplitter 内部“两列总宽必须保持不变”的检查可能失败并取消本次拖动，表现为卡住。日志内容/滚动条变化会改变布局，所以清空日志后又能拖。
- 实现：左列改为 `*`，右列改为固定 `360px`（`MinWidth=240`）。分隔条只调整右列的像素宽度，不再走两星列的 `Split` 检查；窗口变宽时多出的宽度优先给主日志，日志内容不会反过来限制右侧栏。
- 补充（2026-11-11）：固定像素宽后右列可以无限往左拉，整个 Grid 会溢出，跨列的发送区按钮被推到窗口外（关闭串口触发重新布局时最明显）。现在按窗口宽度动态设置右列 `MaxWidth = MainGrid.ActualWidth - 主日志 MinWidth(240) - 分隔条宽度`，拖到最大时仍给日志留 240px。
