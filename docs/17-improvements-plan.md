## 二、推荐批次

### 批次 1：快速修复（约 1.5–2 天）

1. **IMP-11 接口文档链接**：改 `Tools.Global.apiDocumentUrl` 指向本项目 `LuaApi.md`。
2. **IMP-05 表地址补零**：输入 `1` / `123`，回车或失焦后补成 12 位。
3. **IMP-06 DI 位数限制 + 自定义操作码**：输入只允许 4 字节 HEX；操作下拉增加“自定义”，可输入控制码。
4. **IMP-14 快捷发送按钮**：六个文字按钮改为图标 + Tooltip，保持现有命令。
5. **IMP-12 `changlog/index.html`**：删除旧上游页面，或改成跳转本项目 Releases 的简单页面。
6. **IMP-01 多行复制**：先确认是“流式日志文本框”还是“分包模式列表”；列表改为多选 + Ctrl+C/右键复制，文本框补“复制全部”。

### 批次 2：645 通讯增强（约 4–6 天）

依赖：先补 645 串口会话（接收缓冲、帧提取、请求/应答匹配、超时）。

1. **IMP-03 自动读表地址**：地址框右侧圆形按钮，发送 `AAAAAAAAAAAA` 读地址帧；成功后回填、变绿、Tooltip 显示地址。
2. **IMP-02 接收帧减 33H**：建议在 645 页面内增加“通讯日志/应答”区域，解析完整帧后显示减 33H 的数据；不建议直接改主日志的全局显示逻辑。
3. **IMP-04 + IMP-07 数据标识体系**：合并实现。
   - `dlt645-di.json` 保存用户自定义 DI；
   - 导入/导出；
   - 搜索（名称/DI）+ 分类；
   - 内置目录 + 用户目录合并，按 DI 去重，用户可覆盖内置项。

### 批次 3：全局体验（约 2–3 天）

1. **IMP-08 快捷键**：先做窗口内固定快捷键，使用 WPF `InputBindings`，不引入第三方库；全局热键和自定义按键暂不做。
2. **IMP-10 小工具列表**：先做置顶和收藏，工具数量再增长时再加搜索；与 IMP-09 的内部工具注册表合并。
3. **IMP-13 配置导入导出**：直接复用 `settings.json`，加文件选择和确认；导入后提示重启生效。

### 批次 4：架构预研（先 2–3 天出方案）

**IMP-09 插件化**分两级：

- **内部工具注册表**（低风险）：每个小工具提供 Id、标题资源键、图标、页面工厂；ToolSelector 由注册表生成。解决排序、隐藏、后续插件接入点。
- **外部 DLL 插件**（高风险）：需要插件接口、版本兼容、WPF 资源、程序集加载、信任/签名、更新分发。首版不建议直接做。

建议先做内部注册表 + 插件接口设计文档，外部插件等工具数量和需求明确后再立项。

## 三、逐项评估

### IMP-01 输入日志多行复制

- 现状：流式模式是 `TextBox`，理论上支持跨行选择；分包模式 `DataShowPage.xaml` 的 `MainList` 是 `SelectionMode="Single"`，只能单行选择，这与“只能复制一行”的现象吻合。
- 方案：
  - `MainList` 改为 `SelectionMode="Extended"`；
  - 增加 Ctrl+C / 右键“复制选中行”，按选中项拼接 `DataText`/`RawText`；
  - 流式 `MainTextBox` 增加右键“复制全部”。
- 风险：虚拟化列表选中项跨屏时复制顺序要按 Items 顺序，而不是点击顺序。
- 需要确认：“输入日志”是否指分包模式列表；如果是发送记录弹层，则改发送记录列表多选复制。

### IMP-02 645 接收数据帧减 33H 选项

- 现状：645 页面目前只有“粘贴帧解析”，没有实时接收区；主日志显示串口原始字节。
- 方案建议：**在 645 页面内增加独立通讯日志**，订阅串口数据、拼帧、校验，减 33H 后显示。这样“仅 645 生效”语义清晰，也不污染主日志。
- 不建议：按当前工具页动态改写主日志编码，容易出现“同一串数据在不同页面显示不同”的困惑。
- 依赖：645 会话/拼帧/超时（IMP-03 同一套基础设施）。
- 风险：粘包/分包、前导 FE 数量、非 645 数据混入；需要“原始/解码”切换或两栏显示。

### IMP-03 有表地址响应后回填

- 方案：
  - 地址框右侧圆形状态按钮；
  - 点击发送 `FE...68 AAAAAAAAAAAA 68 13 00 CS 16`；
  - 等待应答，匹配读地址应答 `0x93`；
  - 成功：回填 12 位地址、按钮变绿、Tooltip“已连接：xxx”；
  - 失败：灰色/红色 + 具体原因（超时、校验失败、异常应答、多应答）。
- 多表同时应答时不要随便取第一个，应提示用户选择。
- 依赖：645 会话；与 IMP-02 合并实现。
- 预估：1–2 天（不含多应答选择 UI）。

### IMP-04 数据标识可配置、可导入

- 方案：
  - 用户配置放 `ProfilePath/user_dlt645/dlt645-di.json`；
  - Schema：`version`、`categories`、`items[]`（`code`、`name`、`category`、`unit`、`decimals`、`note`）；
  - 内置目录 + 用户目录合并，按 `code` 去重，用户项覆盖内置项；
  - 导入/导出只处理用户层，避免升级时覆盖内置项；
  - 校验：4 字节 HEX、名称非空、重复 code 提示。
- 与 IMP-07 合并，避免做两套列表模型。
- 风险：不同表/厂家的 DI 长度、小数位不同，配置里要允许“仅名称/分类，不做数值解码”。

### IMP-05 表地址输入自动补零

- 方案：回车/失焦时去掉空格；纯数字 1–12 位则 `PadLeft(12, '0')`；含 `AA` 通配则保持；非法字符提示。
- 注意：当前 `MaxLength="12"` 已限制最大长度，但不会自动补零。
- 预估：0.25 天。

### IMP-06 限制 DI 位数 + 操作码输入

- 方案：
  - DI 输入过滤为非十六进制字符，最多 8 个 HEX 字符（4 字节）；
  - 操作下拉增加“自定义控制码”，选中后显示控制码输入框；
  - 自定义控制码发送前提示确认（尤其非读操作）。
- 风险：自定义控制码可能生成无效/危险帧；发送确认和错误提示必须保留。
- 预估：0.5–1 天。

### IMP-07 数据标识搜索与分类

- 方案：参考 `ScriptPickerBar`：
  - DI 下拉/弹层支持搜索名称和 HEX；
  - 分类来自配置文件的 `category`，未分类归入“未分类”；
  - 最近使用可后续再加。
- 与 IMP-04 同一数据源，不冲突；搜索/分类只作用于“合并后的目录”。
- 预估：与 IMP-04 合并约 2–3 天。

### IMP-08 快捷键

- 方案：
  - 第一版用 WPF `InputBindings`/`KeyBinding` + 现有 Command，窗口内生效；
  - 建议只做高频项：开关串口、聚焦发送框、清空日志、打开设置；
  - 不引入第三方库；全局热键（应用失焦也生效）需要 `RegisterHotKey`，首版不做；
  - 可配置快捷键作为后续设置页功能。
- 需要避让系统/编辑器已有快捷键（Ctrl+C/V/A/Z、Ctrl+Enter 等）。
- 预估：固定快捷键 0.5–1 天；可配置 2–3 天。

### IMP-09 小工具插件化

- 可行性：技术上可行，但成本高。
  - 内部注册表：风险低，0.5–1 天；
  - 外部 DLL：需要插件契约、程序集加载、WPF 资源合并、版本兼容、安全信任、安装/更新；1–2 周起。
- 建议：先做内部工具注册表和插件接口文档；外部插件单独立项，做 PoC 后再决定。
- 风险：.NET Framework 4.6.2 无现代插件隔离；恶意插件等同本机代码执行，必须有信任提示/白名单。

### IMP-10 小工具列表搜索/置顶/收藏

- 方案：复用 `ScriptMetadataStore` 思路，增加 `tools.index.json`（favorite/order）；
- 工具数量目前不多，建议先做置顶/收藏，搜索等超过 12–15 个工具再加；
- 与 IMP-09 的内部注册表一起做，避免重复维护工具列表。

### IMP-11 接口文档链接

- 现状：`Global.apiDocumentUrl` 仍指向 `chenxuuu/llcom`。
- 方案：改为本项目 `https://github.com/Eureka12138github/llcom-y/blob/master/LuaApi.md`。
- 5 分钟，可立即做。

### IMP-12 `changlog/index.html`

- 现状：是上游旧版更新日志，代码和自动更新均未引用；自动更新使用 GitHub Releases。
- 方案：删除，或替换为只跳转本项目 Releases 的简单页面；目录名 `changlog` 拼写保持，避免外部链接失效。
- 风险：如果 GitHub Pages 正在使用该页面，删除会导致 404；需先确认 Pages 配置。

### IMP-13 软件配置导出/导入

- 现状：配置已经是单一 `settings.json`，理论上复制文件即可。
- 方案：设置页增加导出/导入按钮；导入前校验 JSON、备份旧配置、导入后提示重启；不做逐项合并。
- 风险：窗口位置、语言等机器相关项；可导出全部，导入后由用户自行调整。
- 价值有限，可作为低优先级/按需实现。

### IMP-14 “快捷发送”按钮 UI 优化

- 现状：快捷发送下方是两列文字按钮（添加、删除、导入、导出、清空、SSCOM 导入）。
- 方案：改为一行图标按钮 + Tooltip，使用现有 `IconButton`/FontAwesome 风格；危险操作（清空）保留文字或二次确认。
- 预估：0.5 天。

## 四、依赖与冲突

1. **IMP-02 / IMP-03**：都依赖 645 串口会话（接收缓冲、拼帧、超时、请求应答匹配），应一起设计。
2. **IMP-04 / IMP-07**：共用 DI 配置与合并目录，必须先定 Schema，再做搜索/分类。
3. **IMP-09 / IMP-10**：内部工具注册表是两者共同基础。
4. **IMP-06** 的自定义控制码与写操作确认要统一安全策略。
5. **IMP-01** 需先确认具体区域；不同区域实现方式不同。

1. 先做批次 1 的 IMP-11、IMP-05、IMP-06、IMP-14、IMP-12。
2. 645 真实电表到位后，集中做批次 2（IMP-03 + IMP-02 + IMP-04/07）。
3. 批次 3 按使用频率决定快捷键和工具列表功能。
4. IMP-09 只做预研和内部注册表，不直接引入外部插件机制。
